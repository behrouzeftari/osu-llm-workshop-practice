Lesson 1: Understanding Permissions

Every file and directory on a Linux system has permissions that control who can read, write, or execute it. When you run ls -l, the first column shows these permissions.

The ls -l output

$ ls -l notes.txt
-rw-r--r-- 1 alex students 1248 Nov  9 10:30 notes.txt

Breakdown of the first field (-rw-r--r--):

PositionCharacterMeaning
1-File type (- = regular file, d = directory, l = symlink)
2–4rw-Owner permissions: read, write, no execute
5–7r--Group permissions: read only
8–10r--Others (everyone else): read only

The three permission bits

LetterNameOn a fileOn a directory
rReadView file contentsList directory contents (ls)
wWriteModify file contentsCreate/delete/rename files inside
xExecuteRun as a program/scriptEnter directory (cd), access files within

Key insight

Execute on a directory is not about running the directory — it's about traversing it. Without x on a directory, you can't cd into it or reach files inside, even if you have read permission on those files.

Who are "owner", "group", and "others"?

  • Owner — the user who created the file (or the user assigned by chown)
  • Group — a named group of users; all members share these permissions
  • Others — everyone else on the system

Use ls -l to see owner and group names. Use id to see your own user and groups.

Practice: decode these

For each string, say who can do what:

  1. drwxr-x---
  2. -rwx------
  3. -rw-rw-rw-
  4. lrwxrwxrwx

For drwxr-x---, explain in your own words: what type of thing is this, and what can the owner, group members, and others do with it?

Why does a directory need the execute (x) bit for someone to cd into it or read a file inside it, even if they have read (r) on the directory?
